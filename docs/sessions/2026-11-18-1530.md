## Leçons de méthode
- **Un `.env` vide doit se distinguer de l'absence par un fichier, pas par un message** : le test « `.env` vide, pas de variable réelle » asserte qu'il ne reste que `.env` dans le dossier (le mutant « traité comme absent » créerait `quiz.db`) ; le test symétrique asserte `['.env', 'real.db']` (le mutant « le `.env` prime » créerait un autre fichier ou refuserait).
- **Le dossier de travail liste ce que le hub a fait** : `readdirSync(workDirectory)` tue le mutant « JWT après l'ouverture de la base » même quand la valeur du secret est valide pour le reste ; sans lui, l'ordre ne se prouve qu'avec une base inutilisable.
- **Une valeur à ne pas reprendre doit exister** : absent et vide n'ont rien à reprendre ; seul le cas des 31 caractères (`k` ×31, distinct du secret de test) tue le mutant « valeur reprise ».
- **Les mutants de sortie (g) tuent presque tout** : ils ne distinguent rien ; ce sont (a), (b), (d), (e), (f), (h) qui disent ce que chaque test mord.
- `dotenv` 17.4 n'écrit rien sur la sortie standard quand un `.env` est lu (vérifié à la main) ; les tests `.env` n'assertent pourtant pas la sortie standard vide, seul le test sans `.env` le fait.
