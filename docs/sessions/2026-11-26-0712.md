## Ce qui change (comportement observable)
- `DELETE /api/v1/themes/:id` avec un `:id` mal formé (forme `8-4-4-4-12` hexadécimale non respectée) : `400 INVALID_UUID`, service jamais appelé (avant : `404`). CA-29a.
- `GET /api/v1/themes/:id` avec un id bien formé de version autre que 7 (ex. `018e4f5a-0000-0000-0000-000000000000`) : `404 NOT_FOUND` (avant : `400`). CA-10. Un id mal formé reste `400 INVALID_UUID` (CA-11).
- `DELETE` : le `Content-Type` est ignoré quelle que soit sa valeur (CA-31a, décision #82). Sondé avant correction sur `app.inject` : `application/xml`, `application/x-www-form-urlencoded`, `application/octet-stream`, valeur qui n'est pas un type de média, valeur vide, avec ou sans corps, et corps sans en-tête répondaient `415` ; `text/plain` répondait déjà `204`. Corrigé (dette soldée).
- `PUT` : même réponses qu'avant, mais le `:id` du chemin et l'`id` du corps passent par le validateur injecté (`UuidFormatValidator` en production), plus par une instance en dur.

Non observable :
- `theme-route.ts` n'utilise plus qu'un seul validateur, `options.uuidValidator`, pour `GET`, `PUT` et `DELETE` ; `index.ts` lui donne `UuidFormatValidator`.
- **`Uuidv7Validator` supprimé** (fichier et test). Justification : après ce changement il n'avait plus aucun usage dans `src` (seul son propre test l'importait) ; le producteur d'ids reste `Uuidv7Generator`, qui garantit la version 7 (CA-5) ; le conserver serait du code mort, contraire à YAGNI. Condition de réouverture inscrite en dette (besoin de contrôler la version 7 hors du producteur). Le test supprimé couvrait aussi des mutants survivants (dette).
- Mécanisme du `Content-Type` du `DELETE` : le plugin enfant retire l'en-tête dans un hook `onRequest` (après l'authentification et le rate limit hérités) et porte un parseur `*` qui ignore le corps. Choix de l'agent, non venu du CDC.

## Leçons de méthode
- `npm ci` échoue sur `better-sqlite3` sous Node 22 faute d'accès à nodejs.org (403 du proxy pour les en-têtes) ; `npm ci --ignore-scripts` puis `npm rebuild better-sqlite3 --nodedir=/opt/node22` (en-têtes locaux) suffit, sans toucher la configuration du dépôt.
- Une dette qui dit « le CDC dit X, le code fait Y » doit être sondée avant d'être crue : le `DELETE` ne tenait pas CA-31a au-delà de `text/plain` (dette sondée le 2026-11-25) ; la sonde jetable (hors dépôt, non committée) a montré qu'un parseur `*` ne suffisait pas pour un en-tête vide ou qui n'est pas un type de média (rejetés par Fastify avant le choix du parseur), d'où le hook.
- Les tests du `PUT` écrits avec l'instance en dur ne prouvaient pas le validateur injecté : un test né vert ne prouve rien tant que la mutation « instance en dur » ou « validateur v7 » n'est pas posée.
