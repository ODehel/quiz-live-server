## Leçons de méthode
- **Un test qui ne s'exécute que dans un environnement précis se prouve dans cet environnement** : les mutants ont été lancés sous un compte non-root dédié, sinon les nouveaux tests sautent et ne prouvent rien. La suite sous root montre seulement le saut (10 sautés annoncés), jamais une preuve.
- **Sonde synchrone au chargement** : `it.skipIf` se décide à la collecte. Le port privilégié se sonde par un processus enfant `spawnSync` (connexion puis écoute), les permissions par un fichier `chmod 000` et un dossier `chmod 555` jetables ; pas d'`await` de premier niveau (le paquet est en CommonJS, `tsc` le refuserait).
- **Nettoyage** : un dossier en lecture seule ne se vide pas ; `afterEach` rend les droits (`restorePermissions`) avant `rmSync`, pour tous les tests (sans effet sur les autres). Aucun dossier `quiz-hub-*` laissé dans `/tmp`.
- **Le préfixe du test sert aussi de filtre** : les trois mutants « sortie » (a, b, f, g) tuent presque tous les tests de refus à la fois ; c'est le mutant (c) puis (c2) qui distingue l'ouverture de la première instruction, et (e) qui distingue le démarrage sur lecture seule.
- Fixtures : la base à trois tables est celle que le hub crée (hub lancé une fois, puis tué), pas celle du seed ; le seed y ajoute les onze comptes pour l'écriture `500` (leçon du 1456).
