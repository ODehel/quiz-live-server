## Décision

**#36** : `Retry-After` vaut toujours `60`, jamais le temps restant. `error-codes.md` et `SECURITE-TRANSVERSALE.md` (tableau, plus un cas dans l'annexe `CA-RateLimit`) le disent. ## Leçons de méthode

- **Un CA littéral peut cacher deux lectures** : `Retry-After: 60` dans quinze CA, et les tests nés verts d'une session précédente assertaient `60` sur un premier `429`, où constante et temps restant coïncident. Seul le smoke test sur le hub réel, un `429` obtenu plus tard dans la fenêtre, a montré l'écart. Un test de header de délai doit laisser passer du temps avant le `429`.
- **Environnement** : Node 22, `npm ci --ignore-scripts` (sans `better-sqlite3` natif : `npm ci` seul échoue sur `node-gyp`), pas de PowerShell, `scripts/session-close.ps1` non exécuté : ce handoff est écrit à la main sur le modèle de `TEMPLATE.md`.
