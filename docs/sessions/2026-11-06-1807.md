## Leçons de méthode

- **Une branche partagée n'impose rien sur l'ordre des tests.** Un seul rouge, un seul vert : pas d'alternance à arbitrer, contrairement aux deux sessions précédentes. Le cadrage l'avait annoncé.
- **La cible A / B se tranche sur le texte littéral.** Le CA-36 dit « sans détails techniques » ; le log vient de l'annexe `SECURITE-TRANSVERSALE.md`, pas du CA. Le log est donc une session à part. Contrepartie assumée : entre les deux commits, le `500` reste muet dans les logs.
- **Sept mutants, un seul test pour les tuer.** Ils ne prouvent rien sur `POST`, `GET /:id` et `DELETE`, qui passent par la même branche sans test propre. Choix fait de ne pas en ajouter ; la couverture par route repose sur le partage de la branche.
- **Imprécision de la PR #36, corrigée ici.** J'y ai écrit que le message en littéral relevait déjà de la dette « Messages d'erreur en dur » ; la ligne ne le listait pas. Ajouté dans ce commit.
- **`gh pr create` échoue dans les sessions Claude Code** (GraphQL bloqué, HTTP 403). Route qui marche : `gh api repos/ODehel/quiz-live-server/pulls -f title=… -f head=… -f base=main -F body=@fichier` (REST).
- **Tâche « PR » marquée terminée trop tôt.** Le `TaskUpdate` est parti dans le même lot que l'appel `gh` qui échouait. Rouverte aussitôt, sans effet sur la PR. Règle : ne pas clore une tâche dans le lot de l'appel qui la valide.
- **Un hook de fin de session a signalé un commit « non poussé »** alors que la branche distante pointait déjà sur `b7b4da7` (vérifié par `git ls-remote`). Faux positif, deuxième session de suite.
