## Choix à challenger
- **(a) Place dans l'ordre** : le contrôle passe en premier, avant l'ouverture de la base, donc avant la table (CA-7), les mots de passe (CA-4) et `BCRYPT_COST` (CA-6), par cohérence avec US-001 (variable de chemin avant l'ouverture). Conséquence observable : `SQLITE_DB_PATH` vide l'emporte sur tout autre refus, et aucun fichier n'est créé (aujourd'hui, un refus de mot de passe laisse un `quiz.db` vide). Alternative écartée : après la lecture de la table, impossible sans ouvrir la base.
- **(b) Forme** : nouveau CA-8 plutôt qu'extension du CA-6, qui dit l'inverse (vide vaut absente pour `BCRYPT_COST`) ; même raison que #57 pour le CA-10 du hub.
- **(c) Flux** : le CA-8 nomme la sortie d'erreur (décision du brief) ; les CA-4 et CA-6 ne nomment pas le flux (le code écrit déjà sur la sortie d'erreur).
- **(d) `.env`** : `SQLITE_DB_PATH=` vide dans `.env` refusé comme toute chaîne vide (conséquence de #52 et #57, non sondée après coup puisque le code n'est pas conforme).
- **(e) Message** : exemple `User seeding failed: SQLITE_DB_PATH cannot be empty.` reprend le préfixe du seed ; non normatif (#53).
