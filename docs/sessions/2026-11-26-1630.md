## Choix d'implémentation (non observables)
- Un seul fichier `src/common/reject-unsupported-content-type.ts` qui exporte le hook ; `declaredCharset` reste privé au fichier. Nom repris de `token-route.ts`.
- Pas de test unitaire dédié au module : il est couvert par les tests de route des thèmes et du token (YAGNI).
- `removeContentTypeParser('text/plain')` n'est pas touché (dette distincte).

## Leçons de méthode
- Un mutant « seul le premier paramètre est lu » a survécu tant qu'aucun test de refus ne plaçait le `charset` après un autre paramètre ; les cas d'acceptation seuls ne l'attrapent pas.

## Prochaine cible proposée
Poser le même contrôle sur les routes de `questions/` (`POST`, `PUT`) : un `Content-Type` absent, vide ou à `charset` non conforme répond `415` avant le corps ; sonder d'abord l'état réel (dette « Conformité à la décision #82 non sondée sur les questions »).
