## Leçons de méthode
- **Correction d'une erreur de ma part** : le handoff `2026-11-01-1334` et la dette disaient que `CA-19a` n'est décrit par aucun CA. Faux : la spec le décrit en annexe. Une étiquette « fausse » se vérifie dans la spec, pas dans le seul corps du test. Corrigé dans `DEBTS.md` ; le handoff `1334` garde l'erreur (« le réel corrige le handoff »).
- **Une fixture à trois lignes tue tous les mutants de tri mono-colonne** : choisir l'ordre voulu pour qu'il diffère de l'ordre d'insertion, de son inverse (`rowid DESC`), des ids et des noms, dans les deux sens. Avec deux lignes, un mutant survit toujours par hasard (leçon de #18, ici poussée plus loin).
- **Sonder avant de planifier** : CA-12 (body de `GET` ignoré) était déjà vrai ; sans cette sonde, j'aurais promis un `fix`.
- **Un test de dépôt qui « existe » peut être faible** : la matrice disait ✅ pour CA-14 au dépôt, les mutations montrent trois survivants. Une case ✅ ne dit pas que le test mord.
- **Lint lancé dès le premier vert** : application de la leçon de #18, zéro aller-retour.
- **Environnement de Claude** (inchangé) : pas de `pwsh`, handoff écrit à la main ; `npm ci --ignore-scripts` ; PR par `gh api` ; `git fetch` de la référence distante après push.
