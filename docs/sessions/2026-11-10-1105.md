## Leçons de méthode

- **Le vert minimal d'un cycle appelle le rouge du suivant** : comparer les seuls champs scalaires faisait passer le SPEED identique, mais traitait un MCQ aux seules `choices` changées comme « inchangé ». Ce second rouge n'a pas été anticipé dans le cadrage ; il s'est imposé en écrivant le test du MCQ.
- **Une comparaison littérale ne se trompe que dans un sens** : elle traite un doute comme un changement (réécrit `last_updated_at`), jamais l'inverse. Le trou de la spec (normalisation, ordre des `choices`) reste donc sans perte de données ; la dette est de précision, pas de justesse.
- **Sonde « après » faussée par un processus resté vivant** : `kill` sur le processus `tsx` laisse le `node` fils sur le port ; la seconde sonde a parlé à l'ancien hub (409 sur le thème déjà créé, aucun id). Tuer par motif (`pkill -f src/index.ts`) et vérifier que le port est libre entre deux sondes.
- **Environnement** : Node 22 au lieu de 26 impose `npm ci --ignore-scripts` ; les tests (SQLite en mémoire) et la sonde tournent, mais ce n'est pas la version de production.
