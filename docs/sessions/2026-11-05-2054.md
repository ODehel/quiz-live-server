## Leçons de méthode

- **Deux routes sans fonction partagée n'imposent pas l'ordre des rouges.** Avec `sendError` (session précédente), le vert du `POST` cassait l'ancien test `PUT`. Ici, `POST` et `PUT` portent chacun leur garde : on aurait pu alterner rouge/vert par route. Choix fait : six rouges d'un coup puis un seul vert, car le vert touche aussi le helper commun. À l'avoir dit à l'avance : la proposition de cadrage parlait d'alternance.
- **Un helper qui renvoie un booléen cache l'information dont le message a besoin.** Le passage de `bodyHasUnknownFields` à `findUnknownFields` s'est fait sous vert, sans test dédié : les cas multi-champs le couvrent, et le mutant « filtre inversé » tombe sur 16 tests.
- **Les mutants ont trouvé une assertion vide.** En lisant les tests CA-27 du `PUT` pour écrire les mutants, `expect(mockThemeService.createTheme).not.toHaveBeenCalled()` s'est révélé sans objet sur cette route (le `PUT` appelle `updateTheme`). Le comportement reste protégé par le statut et le corps. Consigné en dette, non corrigé (hors périmètre).
- **Les étapes de smoke test doivent être complètes de l'environnement, pas seulement du script.** Le premier essai a échoué par ma faute : la dette sur les mots de passe du seed était consignée et je l'ai omise. Règle : relire `DEBTS.md` pour les prérequis d'environnement avant de rédiger un bloc PowerShell.
- **Le test CA-21 s'appelle toujours « should trim the new name »** alors qu'il vérifie un nom invalide (reconduit, à renommer à l'occasion).
- **Les messages de test sont inventés** pour les cas hors champs inconnus (route testée avec un service simulé). Ici, le message `Unknown field(s): …` est produit par la route elle-même, donc asserté pour de bon.
- **Un hook de fin de session a signalé deux fois un commit « non poussé »** alors que la branche distante pointait déjà sur le même SHA (vérifié par `git ls-remote`). Faux positif, aucun effet.
