## Choix d'implémentation (non observables)
- Un hook `onRequest` partagé par `POST` et `PUT`, dans le plugin encapsulé existant, plutôt que deux options de route ou un plugin partagé `common/`.
- Écrit dans `theme-route.ts` (YAGNI), pas dans `common/` : le `charset` (#89) n'est pas décidé pour les thèmes, la factorisation viendra avec lui.
- Le test `!contentType` couvre l'absence et la chaîne vide.

## Leçons de méthode
- Fastify répond déjà `415` dès qu'un corps est présent sans type reconnu ; le seul trou réel était l'absence d'en-tête **et** de corps (Fastify saute alors l'analyse du corps). Le sonder avant de poser le test a évité d'écrire des tests de contrôle non tuables.

## Prochaine cible proposée
Rang 3 (code du JSON invalide, à décider), ou le refus d'un `charset` autre qu'`utf-8` sur les thèmes (#89) avec factorisation du contrôle de `token-route.ts`.
