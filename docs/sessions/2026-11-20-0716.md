## Leçons de méthode
- Le mutant `override` de `dotenv` (`config({ override: true })`) fait écrire à `dotenv` 17 une ligne `injecting env (n) from .env` sur la sortie standard : le test « né vert » du `.env` tombait pour une mauvaise raison (sortie standard non vide). Rejoué avec `quiet: true`, le test de lecture reste vert et seuls les deux tests de priorité (`admin`, `quiz_buzzer_10`) tuent le mutant, sur l'assertion attendue. Un mutant tué n'est pas un mutant tué pour la bonne raison : lire le message d'échec.
- Un mot de passe distinct par compte (`from-the-env-file-<login>`) suffit à tuer les mutants de permutation de comptes sans test dédié.
- Le test de priorité vérifie aussi que les dix autres comptes viennent du `.env` : l'environnement réel ne remplace que la variable en conflit.
